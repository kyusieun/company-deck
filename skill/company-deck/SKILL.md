# 회사 양식으로 새 발표 자료 만들기

사람이 주는 것은 둘이다. 회사 발표 자료(PPT 파일이나 PDF)와 넣고 싶은 재료(대충 쓴 메모, 엑셀, 회의록, 문서, 로고 무엇이든). 결과는 파워포인트에서 고칠 수 있는 PPTX다.
재료는 정리돼 있지 않은 것이 보통이다. 무엇을 말할지 정하고 쪽을 나누는 것까지 AI가 한다.
목표는 하나다. **새로 만든 쪽을 회사 자료의 쪽들과 섞어 놓아도 어느 쪽이 새것인지 구별되지 않아야 한다.**

이 매뉴얼은 여러 번의 제작에서 검사에 걸리고 감별사에게 들킨 뒤 고친 것을 모은 것이다. 어느 회사 양식에도 통하는 것만 적었다.
회사마다 다른 값(색, 크기, 자리)은 여기에 없다. 그 값은 매번 도구가 회사 자료에서 잰다.

## 원칙

1. **사람에게 묻지 않는다.** 판단이 필요하면 스스로 정하고 마지막 보고에 적는다. 중간에 멈추지 않는다.
2. **기계가 할 일은 도구에 맡긴다.** 재기, 틀 그리기, 글자 자리 계산, 검사는 도구가 한다. 직접 눈대중으로 하거나 도구가 한 일을 다시 하지 않는다.
3. **읽는 양을 줄인다.** 요약을 먼저 읽고, 자세한 값은 새 쪽과 짜임이 가까운 회사 자료 쪽 것만 읽는다. 같은 파일을 두 번 읽지 않는다.
4. **양식의 어휘 안에서 만든다.** 회사 자료에 없는 색, 글꼴, 글자 크기, 선 굵기는 쓰지 않는다. 부품은 회사 자료의 치수로 가져오고 배치는 내용에 맞게 새로 짠다.
5. **없는 사실과 숫자를 만들지 않는다.** 글은 재료를 회사 자료의 말투로 다듬어 쓴다. 숫자는 재료에 있는 것만 쓰고, 합계, 증감률, 비율처럼 계산한 숫자에는 계산식을 남긴다.
6. **검사를 통과하려고 규칙을 느슨하게 고치지 않는다.** 규칙이 틀렸다는 것을 회사 자료에서 다시 재서 확인했을 때만 고치고, 고친 이유를 보고에 적는다.

## 폴더와 준비

```
자료/          사람이 준 것 (회사 발표 자료 PPT나 PDF, 메모, 엑셀, 문서, 로고 같은 그림)
작업/양식/     양식을 잰 결과 (도구가 만든다. 같은 회사 자료로 다시 만들 때는 그대로 다시 쓴다)
작업/          재료.md(재료 모음), 구성.md, rules.json, build.js, 그림, 검사 기록
결과/          발표자료.pptx, 발표자료.pdf, 쪽 그림, 보고.md
```

도구는 이 스킬 폴더의 `tools/` 안에 있다. 아래에서 `T`는 그 경로다. 한글이 깨지면 명령 앞에 `PYTHONIOENCODING=utf-8`을 붙인다.

처음 한 번 확인한다. 없는 것은 스스로 설치한다.

```
python --version        # 없으면: 윈도우 winget install -e --id Python.Python.3.12 / 맥 brew install python
node --version          # 없으면: 윈도우 winget install -e --id OpenJS.NodeJS.LTS / 맥 brew install node
python -c "import fitz, PIL, openpyxl, docx"    # 없으면: pip install pymupdf pillow openpyxl python-docx
ls T/node_modules/pptxgenjs     # 없으면: T 폴더에서 npm install
```

맥에서 `python`이 없으면 `python3`, `pip` 대신 `pip3`를 쓴다. 아래 명령도 같다.
파워포인트가 설치돼 있어야 한다. 만든 장표를 파워포인트로 그려 보고 검사하는 데 쓴다(윈도우와 맥 모두). 시작할 때와 끝날 때 `date +%s`로 시각을 적는다.

**도구가 이 컴퓨터에서 안 돌면 멈추지 말고 같은 일을 하는 다른 길을 찾는다.** 도구는 시간과 비용을 아끼려고 만든 지름길일 뿐이다. 운영체제, 설치된 프로그램, 권한 창 때문에 막히면 스스로 판단해서 우회한다.
- 파워포인트로 그리기(`render.py`)가 안 되면: 이 컴퓨터의 파워포인트를 다른 방법으로 부려 PPTX를 PDF로 저장한다. 파워포인트가 없으면 LibreOffice 같은 다른 프로그램으로 그린다. 이때는 글자 자리 보정이 조금 어긋날 수 있으니 자리 검사에서 0.5pt 안의 어긋남은 넘어가고 보고에 적는다.
- 글꼴 폴더를 못 찾으면: 이 컴퓨터의 글꼴 목록을 직접 찾아 쓴다.
- 설치가 막히면: 이 컴퓨터에 맞는 설치 방법을 찾는다.
- 파워포인트나 운영체제가 띄운 창(맥의 파일 접근 허용 같은)이 떠서 멈추면, 그 창 없이 되는 방법으로 바꾼다. Claude Code가 사용자에게 묻는 권한 확인은 우회하지 않는다.
- 우회한 것은 모두 보고에 적는다.
파일 이름은 사람마다 다르다. 이름에 기대지 말고 아래 1단계의 `gather.py`가 고른 회사 양식과 모은 재료를 쓴다.

## 순서

### 1. 재료를 모으고 양식을 준비한다 (도구 두 번)

```
python T/gather.py 자료 작업/재료.md
```

회사 양식을 고르고(PPT 파일이면 파워포인트로 PDF를 만든다), 나머지 재료(글, 엑셀, 워드, 다른 PDF)를 `작업/재료.md` 한 파일에 모은다. 첫 줄에 고른 회사 양식이 나온다. 재료는 이 파일 하나만 읽는다. 원래 파일을 다시 열지 않는다.

`작업/양식/양식요약.md`가 이미 있으면 다음 명령은 건너뛴다.

```
python T/prepare.py <gather.py가 고른 회사 양식> 작업/양식
```

재기, 글자 자리 보정, 틀 뽑기, 검사 규칙 초안까지 한 번에 한다. 끝나면 이것만 읽는다.

| 읽을 것 | 내용 |
|---|---|
| `작업/양식/양식요약.md` | 글자 단계, 줄 간격, 색, 선 굵기, 틀, 본문 범위, 쪽별 한 줄 |
| `작업/양식/overview.jpg` | 전체 쪽 한눈에 보기 |

- "이 컴퓨터에 없는 글꼴"이 나오면 가장 가까운 설치 글꼴로 바꾸고 보고에 적는다.
- 제목이나 쪽 번호가 "윤곽선 글자"로 나오면 그 쪽 그림에서 글을 읽어 아래를 돌린다. 글꼴, 크기, 기준선이 자동으로 정해진다.
  ```
  python T/peek.py fit-frame 작업/양식 title <쪽> "<그 쪽 제목에 적힌 글>"
  ```

그다음 규칙 초안을 복사한다. `cp 작업/양식/rules.draft.json 작업/rules.json`

### 2. 구성을 짠다

`작업/재료.md`를 읽고 `작업/구성.md`에 발표 자료의 차례를 적는다.

- **먼저 이 자료의 결론을 한 문장으로 정한다.** 재료에 결론이 적혀 있지 않으면 숫자와 메모에서 가장 중요한 변화를 결론으로 삼는다. 정한 결론과 이유를 보고에 적는다.
- **재료의 요청을 따른다.** 메모에 쪽 수, 넣을 것, 뺄 것, 보고 대상이 적혀 있으면 그대로 한다. 쪽 수가 없으면 결론을 받치는 데 필요한 만큼만 만든다(본문 대여섯 쪽이 보통이다).
- **엑셀은 필요한 칸만 쓴다.** 재료의 표를 통째로 옮기지 않는다. 결론에 필요한 행과 열만 고르고, 월별 숫자가 많으면 분기나 누계로 묶어 계산식을 남긴다. 합계 행이 이미 있으면 그 값을 쓴다.
- **메모끼리 숫자가 다르면** 엑셀 같은 원자료의 숫자를 쓰고 보고에 적는다.
- **회의록의 말은 결정과 할 일만 가져온다.** 누가 무슨 말을 했는지는 장표에 넣지 않는다.

- **쪽마다 전할 말은 하나다.** 메모의 내용을 전할 말 단위로 나눈다. 한 쪽에 다 넣지 않는다.
- **쪽의 종류는 회사 자료에 있는 것 가운데서 고른다.** 숫자의 흐름은 차트 쪽, 항목이 많은 숫자는 표 쪽, 계획과 관계는 도식 쪽, 설명은 글 쪽. 회사 자료가 그런 내용을 어떻게 보여주는지 쪽별 한 줄에서 찾는다.
- **표지, 간지, 맺음 쪽은 회사 자료에 있으면 넣는다.** 간지는 본문이 여섯 쪽을 넘을 때만 넣는다.
- **글은 회사 자료의 말투로 쓴다.** 끝맺음(명사로 끝나는지, 문장인지), 글머리표 모양, 한 줄의 길이를 회사 자료에서 본다. 재료가 길면 줄이고, 재료에 없는 사실은 보태지 않는다. 메모의 말버릇(반말, 줄임말, 물음표)은 장표에 옮기지 않는다.
- **쪽 번호는 새 자료의 차례대로 매긴다.** 회사 자료가 표지와 간지에 번호를 찍지 않으면 따른다.

쪽마다 적는다: 전할 말, 쪽의 종류, 짜임이 가까운 회사 자료 쪽(두세 쪽), 들어갈 글과 숫자.

### 3. 쪽을 짠다

쪽마다 짜임이 가까운 회사 자료 쪽을 **두세 쪽만** 골라 그림(`작업/양식/pages/pNN.png`)과 잰 값(`작업/양식/dump/pNN.txt`)을 읽는다. 여러 쪽이 같은 회사 자료 쪽을 참고하면 한 번만 읽는다.
`작업/구성.md`에 가져올 부품과 치수, 좌표로 쓴 배치를 덧붙인다.

- **본문 쪽**은 부품과 치수를 가져오고 배치는 내용에 맞게 새로 짠다. 짤 때 지킬 것은 아래 '처음부터 피할 것'에 있다.
- **표지, 간지, 맺음 쪽**은 회사 자료의 같은 쪽을 그대로 따라 그리고 글만 바꾼다. 이 쪽들은 틀(`s.frame()`)을 쓰지 않는다. `rules.json`의 `no_chrome_slides`에 그 쪽 번호를 넣는다.
- **회사 자료에 있는 정보 칸을 재료로 채우지 못하면 지우지 않는다.** 발표일, 부서, 발표자, 연락처, 출처 같은 칸이 회사 자료에 있는데 재료에 없으면, 그 자리에 같은 글꼴과 크기로 `[자료 없음: 연락처]`처럼 적는다. 재료가 애매해서 확정할 수 없는 값("다음주 화요일"처럼)은 `[확인 필요: 발표일]`로 적는다. 사람이 열어 보고 바로 채울 수 있게 하기 위해서다. 이런 칸은 보고와 마지막 답에 목록으로 적는다.

### 4. 그림을 준비한다

- 사람이 준 로고나 그림은 그대로 쓴다. 크기는 회사 자료에서 같은 종류의 그림이 쓰인 크기를 따른다.
- 회사 자료에 있던 그림은 `작업/양식/images/`에 있다.
- 없는 아이콘은 코드로 그린다(SVG를 PNG로). 회사 자료 아이콘의 선 굵기와 색을 재서 같은 결로 맞춘다. 회사 자료에 아이콘이 없으면 아이콘을 쓰지 않는다.
- 만든 그림은 `python T/clean_assets.py 작업/그림 작업/그림/clean --ref <회사 자료에서 잘라낸 같은 종류의 그림>`으로 검사한다.
- **재료에 우리 회사 로고가 있거나 로고, 회사 이름을 바꾸라는 말이 있으면** 틀의 그림을 바꾼다. `s.frame({ ..., swap: { "<양식요약의 틀 이름>": "자료/로고/새로고.png" } })`. 바꾼 그림의 틀 규칙은 `rules.json`의 `chrome`에서 빼고 보고에 적는다. 표지와 맺음 쪽의 로고도 같이 바꾼다. 그런 것이 없으면 틀을 건드리지 않는다.

### 5. 만든다

`작업/build.js`를 쓴다. `T/lib.js` 첫머리의 설명을 먼저 읽는다.

```js
const L = require("T/lib.js");
(async () => {
  const deck = L.newDeck({ widthPt: W, heightPt: H, title: "발표 자료" });   // W, H는 양식요약의 장표 크기
  deck.useStyle("작업/양식");                       // 글자 자리 보정값과 틀을 읽는다
  const s = deck.slide({ name: "본문 1" });
  s.frame({ title: "제목", pageNo: 1 });            // 틀은 이 한 줄로 끝낸다. 직접 그리지 않는다
  s.rect(x, y, w, h, { fill: "......", role: "card_head" });
  s.textAt("한 줄 글", x, 기준선, { font: "MalgunGothicBold", size: 14, color: "000000", role: "card_title" });
  s.paraAt(["첫 줄", "둘째 줄"], x, 첫줄기준선, 줄간격, 너비, { font: "MalgunGothic", size: 12, role: "body" });
  await deck.save("결과/발표자료.pptx");
})();
```

- 글자는 `textAt`과 `paraAt`으로 놓는다. 자리는 회사 자료 dump에 적힌 `시작`과 `기준선` 값을 쓴다. 글 상자 위치를 직접 계산하지 않는다.
- `font`에는 dump에 적힌 글꼴 이름을 그대로 쓴다. 굵기는 이름에서 따라온다.
- 한 줄에 서식이 섞여 있으면(dump의 '섞인 서식') 글을 조각 배열로 준다: `[{ text: "ABC", font: "Arial-BoldMT", size: 24 }, { text: " 가나다", font: "MalgunGothic", size: 20 }]`. 제목도 같다(`s.frame({ title: [...] })`). 제목의 꼴이 쪽마다 다르면 새 쪽과 종류가 같은 회사 자료 쪽의 꼴을 따르고 `titleStyle`로 글꼴, 크기, 기준선, x를 넘긴다.
- 가운데 맞춤은 `align: "center"`와 가운데 x를, 오른쪽 맞춤은 `align: "right"`와 오른쪽 끝 x를 준다.
- 표는 `s.table`, 막대 차트는 `s.barChart`(고칠 수 있는 진짜 차트), 곡선 도형은 `s.freeform`.
- 같은 역할의 요소에는 같은 `role` 이름을 준다. 크기나 높이가 자료에 따라 달라지는 요소(로고, 막대 값 표시)는 요소마다 역할 이름을 따로 준다.
- 좌표는 숫자를 하나씩 적지 말고 계산식으로 만든다. 같은 역할의 요소가 1pt씩 어긋나는 것을 막는다.
- 면을 먼저 그리고 글자를 나중에 그린다.
- 계산해서 만든 숫자는 `source: "계산식"`을 함께 적는다.

### 6. 그리고 검사한다 (실패 0건까지)

```
python T/make.py v1 --pptx 결과/발표자료.pptx
```

이 한 줄이 만들기(`node 작업/build.js`), 파워포인트로 그리기, 글자 자리 미세 보정, 검사를 차례로 한다.

- 실패 목록을 보고 한꺼번에 고친 뒤 꼬리표를 v2로 올려 다시 돌린다.
- 글자 자리가 0.1~0.7pt 어긋나는 것은 도구가 알아서 바로잡는다. `build.js`에서 자리를 손으로 고치지 않는다.
- 실패 0건이 되면 모아 보기 그림(`작업/그림결과/vN_sheet.jpg`)을 열어 본다. 어색한 쪽만 쪽 그림을 따로 연다.
- 눈으로 찾은 문제 가운데 잴 수 있는 것은 계산식으로 바꿔 다시 생기지 않게 한다.
- 숫자 검사는 `작업/재료.md`와 대조한다. 날짜나 쪽 번호처럼 재료에 없어도 되는 숫자는 `rules.json`의 `ignore_text`나 `allowed_text`에 넣고 이유를 보고에 적는다.

### 7. 감별을 받는다

이 작업을 모르는 다른 AI가 쪽 그림만 본다. 새 본문 쪽과 회사 자료의 본문 쪽을 섞어 놓고, 쪽마다 회사가 만든 것인지 AI가 만든 것인지 판정한다.

```
python T/judge.py lineup --originals 작업/양식/pages --pages <회사 자료의 본문 쪽 번호들> --new 작업/그림결과/vN_s02.png 작업/그림결과/vN_s03.png --judge claude --rounds 1 --out 작업/judge_vN_claude.json
```

- `--new`에는 새 본문 쪽만 준다. 표지, 간지, 맺음 쪽은 빼고 준다.
- `codex`(OpenAI) 감별은 **사용자가 요청했을 때만** 받는다. 쪽 그림이 OpenAI로 보내지기 때문이다. 요청이 있으면 `--judge codex`로도 받는다.
- 감별은 몇 분 걸린다. **끝날 때까지 기다린다.** 감별사를 뒤에서 돌려 놓고 일을 끝내면 안 된다. 두 감별사를 함께 돌릴 때는 한 명령 안에서 `명령1 & 명령2 & wait`로 묶는다.
- 감별사는 회사가 만든 쪽도 가끔 AI로 지목한다. 그래서 기준은 상대 비교다. **새 쪽이 지목된 비율이 회사 자료 쪽이 지목된 비율보다 높지 않으면 통과다.**
- 지목된 쪽은 감별사가 적은 이유를 회사 자료에서 다시 재서 **사실일 때만** 고친다. 회사 자료도 같은 특징을 갖고 있으면 고치지 않는다.
- 고친 뒤 검사를 다시 통과시키고 감별을 한 번 더 받는다. **고치는 것은 두 번까지다.** 그래도 지목되면 남은 문제로 보고한다.
- 통과했으면 다시 받지 않는다.
- 명령줄 감별사가 하나도 없으면 하위 에이전트에게 새 쪽 그림과 회사 자료 쪽 그림을 섞어 주고 같은 판정을 맡긴다. 어느 쪽이 새것인지는 알려 주지 않는다.

### 8. 보고한다

`결과/`에 `발표자료.pptx`, `발표자료.pdf`, 쪽 그림을 둔다. `결과/보고.md`에 적는다: 고른 회사 양식 파일(맨 처음에), 걸린 시간, 구성(쪽마다 전할 말과 참고한 회사 자료 쪽), 검사 회차별 실패 건수, 감별 결과, 정한 결론과 이유, 스스로 정한 것과 이유, 재료에서 줄이거나 뺀 내용, 읽지 못한 파일, 계산으로 만든 숫자, 만든 그림, 고친 규칙, 채워야 할 칸(`[자료 없음]`, `[확인 필요]`로 남긴 곳), 남은 문제. 마지막 답은 짧게 하되 채워야 할 칸은 빠짐없이 적는다.

## 처음부터 피할 것

지난 제작에서 실제로 검사에 걸리거나 감별사에게 들킨 것들이다.

### 틀과 자리

| 실패 | 막는 법 |
|---|---|
| 모든 쪽에 되풀이되는 장식과 선, 아래쪽 표기가 회사 자료와 1픽셀 어긋나 들켰다 | 틀은 `s.frame()`으로만 그린다 |
| 잰 값을 0.1pt 단위로 줄여 넣어 가장자리가 달라졌다 | 잰 값은 소수 둘째 자리까지 그대로 쓴다 |
| 제목에 빗금이나 괄호가 들어가자 글자 높이로 맞춘 자리가 틀어졌다 | 글자는 기준선으로 놓는다 (`textAt`) |
| 같은 역할의 상자가 1.2pt씩 어긋났다 | 좌표를 계산식으로 만든다 |
| 본문이 회사 자료보다 위에서 끝나 아래가 비었다 | 양식요약의 '본문 아래 끝'까지 채운다. 각주가 있는 쪽만 짧다 |
| 글이 상자 너비를 넘쳤다 | 글 길이를 세어 상자 너비와 줄 수를 먼저 계산한다 |

### 색

| 실패 | 막는 법 |
|---|---|
| 투명도가 걸린 색을 그대로 옮겨 더 옅어졌다 | 화면에 보이는 색을 `peek.py colors`로 재서 불투명 색으로 쓴다 |
| 양식에 없는 채움 색이 검사에 걸렸다 | 색은 양식요약의 목록에서만 고른다 |
| 흰 바탕 로고를 색 있는 상자 위에 놓아 흰 네모가 보였다 | 로고는 흰 바탕 위에 놓거나 `clean_assets.py --transparent`로 바탕을 뺀다 |
| 항목의 색이 회사 자료와 달랐다 | 사업, 부문, 제품이 회사 자료에서 자기 색을 갖고 있으면 그 색을 쓴다 |

### 짜임

| 실패 | 막는 법 |
|---|---|
| 다른 쪽의 틀에 글만 바꿔 넣어 매번 들켰다 (판박이) | 부품과 치수는 가져오고 배치는 그 내용에 맞게 새로 짠다 |
| 가져온 상자에 내용이 위에만 몰려 아래가 비었다 | 상자 크기를 줄 수와 항목 수로 다시 계산한다 |
| 묶음마다 내용의 양이 다른데 같은 상자에 넣었다 | 상자 없이 제목과 목록으로 짜거나 묶음 너비를 달리한다 |
| 글만 있는 쪽이 휑했다 | 줄 간격을 회사 자료 글머리표의 줄 간격까지 넓힌다. 글자 크기 단계와 굵기로 위계를 만든다 |
| 내용에 맞는 부품이 있는데 가장 단순한 쪽만 따라 했다 | 짜임이 가까운 회사 자료 쪽을 모두 놓고 사정이 가장 비슷한 쪽의 방식을 고른다 |
| 새 쪽들이 서로 똑같이 생겼다 | 회사 자료는 쪽마다 내용에 맞춰 짜임이 다르다. 새 쪽들도 종류를 섞는다 |

### 글

| 실패 | 막는 법 |
|---|---|
| 메모의 묶음 기호와 지시문이 장표에 들어갔다 | 장표에 넣을 말만 넣는다 |
| 엑셀 표를 통째로 옮겨 글자가 작고 빽빽했다 | 결론에 필요한 행과 열만 고른다. 표의 글자 크기는 회사 자료 표의 크기를 따른다 |
| 줄 끝 문장 부호가 회사 자료의 습관과 달랐다 | 회사 자료가 줄 끝에 쉼표나 마침표를 남기는지 보고 따른다 |
| 굵게 쓰는 말의 경계가 달랐다 | 조사까지 굵은지, 핵심 구절만 굵은지 회사 자료에서 본다 |
| 위첨자는 번호인데 각주는 별표였다 | 본문 표시와 각주 기호의 짝을 맞춘다 |
| 영문과 숫자가 한글 글꼴로 찍혀 글자 폭과 낱말 사이가 회사 자료와 달랐다 | 양식요약에 '영문·숫자 글꼴'이 적혀 있으면 도구가 저장할 때 알아서 맞춘다. 글꼴 이름은 한글 글꼴로 주면 된다 |
| 글이 회사 자료보다 길고 설명하는 말투였다 | 회사 자료의 한 줄 길이와 끝맺음을 따른다 |

### 차트와 표

| 실패 | 막는 법 |
|---|---|
| 값 축 시작이 회사 자료와 달랐다 | 회사 자료의 막대 높이를 값으로 나눠 축이 0에서 시작하는지 잘라 쓰는지 본다 |
| 나란히 놓인 차트의 눈금이 제각각이었다 | 같은 단위의 차트는 눈금을 같이 쓴다 |
| 표 칸 너비가 들쭉날쭉했다 | 값 열은 같은 너비로 나눈다. 줄 높이는 고르게 계산한다 |

### 일하는 방식

| 실패 | 막는 법 |
|---|---|
| 회사 자료 쪽을 전부 읽느라 시간과 비용의 절반을 썼다 | 요약과 가까운 두세 쪽만 읽는다 |
| 글자 자리를 맞추려고 시험 렌더를 여러 번 돌렸다 | 보정값은 `prepare.py`가 이미 구했다. 다시 하지 않는다 |
| 감별사가 틀린 지적을 했는데 그대로 고쳤다 | 지적은 회사 자료에서 다시 재서 사실일 때만 고친다 |
| 통과한 뒤에도 감별을 되풀이해 시간을 썼다 | 통과하면 멈춘다 |
