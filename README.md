# company-deck

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

회사에서 실제로 발표한 자료 한 벌을 본보기로 삼아, 메모·엑셀·회의록으로 같은 양식의 새 발표 자료를 만드는 Claude Code 스킬입니다.

![회사 자료(왼쪽)와 이 스킬로 만든 슬라이드(오른쪽)](assets/side_by_side_1.jpg)

스킬은 도구 묶음이 아니라 작업 방향을 적은 문서 한 장(`SKILL.md`)입니다. 본보기 자료를 코드로 재고, 만든 슬라이드를 다시 재서 검사하고, 작업 내용을 모르는 새 Claude 세션에게 새 슬라이드와 본보기 슬라이드를 섞어 보여 주고 새 것을 골라내게 합니다(아래에서 "감별"). 측정과 검사에 쓰는 코드는 Claude가 그 컴퓨터에 맞게 직접 씁니다. 결과는 파워포인트에서 고칠 수 있는 PPTX입니다.

## 준비물

| 준비물 | 설명 |
|---|---|
| 파워포인트 (권장) | 만든 슬라이드를 파워포인트로 그려서 검사합니다. 없으면 LibreOffice 같은 다른 프로그램으로 그리지만 글자 위치가 조금 덜 정확합니다 |
| Claude 유료 요금제 | 무료 요금제로는 쓸 수 없습니다 |
| Claude Code | [설치 안내](https://code.claude.com/docs/ko/setup)대로 설치하고, 처음 실행할 때 Claude 계정으로 로그인합니다. 모델은 `/model`로 Opus를 고릅니다 |
| 본보기 자료에 쓰인 글꼴 | 없으면 가장 가까운 글꼴로 바꿉니다 |

Python 같은 필요한 프로그램은 Claude가 확인하고 없으면 설치합니다.

작업하는 동안 본보기 자료와 입력 자료는 Anthropic으로 보내집니다. 개인 요금제에서는 설정에 따라 대화 내용이 모델 학습에 쓰일 수 있습니다. 회사 자료를 AI 서비스에 올려도 되는지 소속 회사의 규정을 먼저 확인하세요.

## 시작하기

1. 빈 폴더를 만들고 그 안에 `자료` 폴더를 만듭니다.
2. `자료` 폴더에 넣습니다.
   - **본보기 자료 한 벌** (PPTX 또는 PDF). 빈 템플릿보다 표와 차트가 들어간, 실제로 발표한 자료가 좋습니다. 표·차트·도식의 모양을 이 자료에서 가져오기 때문입니다. **파일 이름에 "양식"을 넣고, 그런 파일은 하나만 둡니다.** 예: `2분기실적_양식.pptx`
   - **이번에 쓸 자료.** 메모(txt, md), 엑셀(xlsx, csv), 워드(docx), PDF, 로고 그림을 읽습니다. 정리하지 않아도 됩니다.
3. 그 폴더에서 Claude Code를 엽니다. 윈도우는 탐색기에서 폴더 빈 곳을 오른쪽 클릭 → "터미널에서 열기", 맥은 Finder에서 폴더를 오른쪽 클릭 → "폴더에서 새로운 터미널 열기"를 한 뒤 `claude` 를 입력합니다.
4. 아래 프롬프트를 붙여 넣습니다. [프롬프트.txt](프롬프트.txt)와 같습니다.

```
https://github.com/kyusieun/company-deck 저장소에서 skill/company-deck 폴더를 받아 이 폴더의 .claude/skills/company-deck 으로 넣어 줘. 받은 저장소 사본은 지우고, 그 안의 SKILL.md를 읽고 그대로 따라 줘.
자료 폴더에 우리 회사 발표 자료(이름에 '양식'이 들어간 파일)랑 이번 발표에 쓸 자료들(메모, 엑셀, 회의록 같은 것)을 넣어 뒀어. 회사 양식 그대로 발표 자료 만들어 줘.
자료에 없는 내용은 지어내지 말고, 나한테 묻지 말고 끝까지 해 줘.
```

권한 설정이 기본값이면 명령을 실행하거나 파일을 쓸 때마다 확인 창이 뜹니다. 허용을 눌러야 진행됩니다.

몇 장으로 만들지, 어떤 순서로 할지는 메모에 적으면 따릅니다. 로고를 바꾸려면 로고 그림을 넣고 메모에 바꿔 달라고 적습니다.

### 결과

| 파일 | 내용 |
|---|---|
| `결과/*.pptx` | 만든 발표 자료 |
| `결과/*.pdf` | PDF로 내보낸 미리 보기 |
| `결과/*.png` | 슬라이드마다 그림과 모아 보기 |
| `결과/보고.md` | 고른 본보기 파일, 정한 결론과 이유, 계산한 숫자와 계산식, 줄이거나 뺀 내용, 감별 결과, 채워야 할 칸, 남은 문제 |

- 글은 글 상자, 표는 표, 차트는 파워포인트 차트로 만들라고 스킬에 적혀 있습니다. 그래도 차트 위의 합계 숫자나 범례 글자처럼 차트와 따로 그려진 부분이 있을 수 있고, 그런 곳은 `보고.md`에 적힙니다.
- 같은 폴더에서 다시 만들면 `결과` 폴더의 파일을 덮어씁니다. 손본 파일은 다른 이름으로 저장해 두세요.

스킬을 새 버전으로 바꾸려면 `.claude/skills/company-deck` 폴더를 지우고 이렇게 보냅니다.

```
https://github.com/kyusieun/company-deck 저장소의 skill/company-deck 폴더를 이 폴더의 .claude/skills/company-deck 으로 받아 두기만 해 줘. 발표 자료는 만들지 마.
```

## 예시: 메모·엑셀·회의록으로 만든 분기 실적 보고

OCI의 공개 실적발표 자료(21장)를 본보기로 쓰고, 가상 회사 "한결소재"의 3분기 영업실적 자료를 넣었습니다. 입력 자료는 시험을 위해 일부러 정리하지 않은 상태로 꾸며 쓴 것입니다.

- 메모 13줄: 결론은 적지 않았고, "장표는 10장 안으로", "로고는 우리 로고로 바꿔주고 회사 이름은 한결소재", "마지막 장에 문의처" 같은 요청이 들어 있습니다.
- 월별 실적 엑셀: 시트 4개에 담당자 칸과 빈 시트가 그대로 있습니다.
- 회의록과 로고 그림.

사람에게 묻지 않고 9장을 만들었습니다. 약 37분 걸렸습니다.

![결과 9장](assets/result_9pages.jpg)

왼쪽은 본보기로 쓴 OCI 자료, 오른쪽은 만든 슬라이드입니다. 번호는 PDF 파일 안의 순서입니다.

![OCI 자료와 만든 슬라이드 비교](assets/side_by_side_2.jpg)

결론과 구성은 AI가 자료를 보고 정했습니다. 회의록에서는 결정 사항과 할 일만 가져왔고, 엑셀에 없던 분기 합계와 증감률은 계산해서 넣고 계산식을 `보고.md`에 남겼습니다. 자료에 없던 맺음 슬라이드의 이메일과 주소는 `[자료 없음]`으로 남겼습니다.

이 작업은 감별을 통과하지 못했습니다. 새 본문 5장과 본보기 본문 12장을 섞어 세 번 보여 줬는데, 세 번 모두 새 5장이 모두 골라졌고 본보기는 한 장도 골라지지 않았습니다. 선에 붙은 그림자, 글자 간격처럼 사실로 확인된 지적은 고쳤고, 마지막까지 남은 이유는 "새 슬라이드끼리 같은 숫자가 되풀이된다", "내용이 적다"처럼 내용에 관한 것이었습니다.

## 동작 방식

```mermaid
flowchart LR
    A[자료 모으기] --> B[본보기 측정]
    B --> C[구성 짜기]
    C --> D[슬라이드 만들기]
    D --> E{검사}
    E -- 실패 --> D
    E -- 통과 --> F{감별}
    F -- 지적됨, 두 번까지 --> D
    F -- 통과 또는 두 번 고친 뒤 --> G[PPTX와 보고.md]
```

1. **자료 모으기**: `자료` 폴더에서 본보기 파일을 고르고, 나머지 자료를 읽어 한곳에 모읍니다.
2. **본보기 측정**: 글자 크기와 줄 간격, 색, 선 굵기, 제목과 쪽 번호 위치, 모든 슬라이드에 되풀이되는 요소를 코드로 잽니다.
3. **구성 짜기**: 결론을 정하고 슬라이드마다 전할 말을 하나씩 나눕니다. 표, 차트, 도식 같은 슬라이드 종류는 본보기에 있는 것 가운데서 고릅니다.
4. **슬라이드 만들기**: 본보기의 부품과 치수를 가져와 새 내용에 맞게 배치합니다.
5. **검사**: 만든 파일을 파워포인트로 그린 결과를 다시 재서, 여백, 되풀이 요소, 글자 크기, 색, 넘침, 자료에 없는 숫자를 확인합니다.
6. **감별**: 작업 내용을 모르는 새 세션(하위 에이전트)에게 슬라이드 그림만 섞어 보여 줍니다. 새 슬라이드가 골라진 비율이 본보기 슬라이드가 골라진 비율보다 높지 않으면 통과입니다. 지적된 이유는 본보기와 대조해서 사실일 때만 고칩니다.

`SKILL.md`에는 순서를 하나하나 정한 명령 대신, 지난 제작에서 검사에 걸리거나 감별에 지적된 것과 시간을 버린 곳이 정리돼 있습니다. 특정 회사의 값, 특정 운영체제의 명령은 들어 있지 않습니다.

## 시험 결과

모두 명령줄(Claude Code CLI)에서 권한 확인을 끈 상태로, Opus 5.5로, 조건마다 한 번씩 돌렸습니다. 비용은 쓴 토큰을 API 정가로 환산한 값입니다. 유료 요금제에서 한 번 돌릴 때 사용량 한도를 얼마나 쓰는지는 재지 않았습니다.

| 시험 | 버전 | 장 | 시간 | 비용 | 감별 |
|---|---|---|---|---|---|
| 위 예시 (OCI, 메모·엑셀·회의록) | 지금 버전 | 9장 | 약 37분 | 10.9달러 (감별 포함) | 통과 못 함 |
| 같은 자료, 빈 폴더에서 위 프롬프트 그대로 (링크로 설치부터) | 지금 버전 (커밋 724bda4) | 10장 | 약 36분 | 10.9달러 (감별 포함) | 통과 못 함 |
| 같은 조건, 감별을 한 장씩 따로 받던 버전 | 커밋 b122087 | 10장 | 약 38분 | 17.1달러 (감별 포함) | 통과 못 함 |
| 같은 자료(발표일·문의처 줄만 없음), 앞선 버전 | 전용 도구 16개가 들어 있던 버전 | 9장 | 약 19분 | 6.5달러 | 통과 못 함 |
| 검증 실험 (삼성SDS, 뺀 세 장 다시 만들기) | 전용 도구 버전 | 3장 | 27분 | 8.9달러 | 아래 표 |

앞선 버전은 측정, 검사, 감별을 하는 전용 도구(Python, Node.js)를 함께 나눠 줬습니다. 윈도우와 파워포인트에 맞춘 부분이 많아 지금 버전에서는 도구를 빼고 방향만 남겼습니다. 같은 자료로 돌렸을 때 결과 품질과 감별 결과는 비슷했고, 시간과 비용은 두 배쯤 들었습니다. 감별을 새 슬라이드 한 장씩 따로 받게 해 본 버전은 비용만 늘고 결과가 같아 되돌렸습니다. 지금 버전은 간격과 줄바꿈이 고르다는 것, 주제와 숫자를 판정 근거에서 뺍니다. 그래도 감별사는 매번 표가 빽빽하다, 띄어쓰기가 회사 자료와 다르다 같은 작은 차이를 찾아냈습니다(새 슬라이드 5장 중 5, 2, 5장 지목).

### 검증 실험: 공시 자료에서 뺀 세 장 다시 만들기

삼성SDS의 2026년 1분기 실적발표 자료(21장)에서 4·5·6번째 슬라이드를 뺐습니다. 남은 18장과 뺀 슬라이드의 글·배치 메모를 주고 다시 만들게 한 뒤 원래 자리에 넣었습니다. 본보기를 얼마나 따라 하는지 재려는 실험입니다.

![삼성SDS 21장 중 4·5·6번째를 AI가 다시 만든 결과](assets/quiz_21pages.jpg)

21장을 모두 두 감별(Claude Fable 5.1, GPT 5.5. 개발 중 비교용으로만 썼고 스킬에는 들어 있지 않습니다)에 각각 세 번 보여 주고 AI가 만든 세 장을 고르게 했습니다. 글이 거의 없는 간지와 맺음 슬라이드를 빼고 아무렇게나 고른다 쳐도, 한 장이 뽑힐 확률은 다섯 번에 한 번 정도입니다.

| 슬라이드 | Claude | GPT | 합계 |
|---|---|---|---|
| 4번째 | 0/3 | 0/3 | 0/6 |
| 5번째 | 0/3 | 1/3 | 1/6 |
| 6번째 | 0/3 | 2/3 | 2/6 |

4번째는 한 번도 골라지지 않았고, 6번째는 아무렇게나 고를 때보다 자주 골라졌습니다. 글과 배치를 정해 준 조건이라, 메모만 주는 실제 사용보다 쉬운 시험입니다.

## 문제가 생기면

- **중간에 멈췄을 때**: 같은 대화에서 "이어서 끝까지 해 줘"라고 보냅니다. 사용량 한도에 걸렸으면 한도가 풀린 뒤에 보냅니다. 창을 닫았으면 그 폴더에서 `claude --continue`로 이전 대화를 연 뒤 보냅니다.
- **글자 모양이 다를 때**: 본보기에 쓰인 글꼴이 PC에 있는지 확인합니다. `보고.md`에 바꾼 글꼴이 적혀 있습니다.
- **읽지 못하는 파일**: 한글(hwp)과 옛 형식(xls, doc, ppt)은 읽지 못할 수 있습니다. PDF나 xlsx, docx, pptx로 다시 저장해서 넣으면 확실합니다.
- **엉뚱한 파일이 본보기로 쓰였을 때**: `보고.md` 첫머리에 고른 파일이 적힙니다. 본보기 파일 이름에 "양식"을 넣고 다시 합니다.

## 제한 사항

- 판정은 모두 감별(AI)이 했습니다. 사람이 결과를 보고 판정한 시험은 없습니다.
- 명령줄에서 권한 확인을 끈 상태로, 윈도우에서만 시험했습니다. 데스크톱 앱과 맥에서는 아직 돌려 보지 않았습니다.
- 회사가 실제로 쓰는 PPTX(슬라이드 마스터와 테마 글꼴이 있는 파일)를 본보기로 넣는 것, 회사 전용 글꼴을 쓰는 본보기는 시험하지 않았습니다.
- 입력 자료는 시험을 위해 꾸며 쓴 것이고, 조건마다 한 번씩만 돌렸습니다. 같은 입력이라도 실행마다 결과가 조금씩 다릅니다.
- 숫자는 자료와 대조해 검사하지만, 쓰기 전에 직접 확인해야 합니다.
